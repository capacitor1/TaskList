# 任务清单 v1.0

一个面向 Windows 的本地待办工具。主页按重要程度与剩余时间展示当前任务，任务库保留全部未结束与已结束任务，支持单次任务与每天 / 每周 / 每月的多次触发，数据保存在程序旁的本地 SQLite 数据库中。

程序为绿色运行方式，无安装程序；复制 `TaskList.exe` 即可使用（框架依赖版需先安装 .NET 8 Desktop Runtime）。所有数据均保存在本机，不依赖账号或网络服务。

## 核心特性

- **主页聚焦当前任务**：只显示已开始、未完成且未过期的任务；单次任务完成后归档，多次任务完成后等待下一次触发。
- **智能排序**：综合重要等级与截止紧迫度排序，重要且临近截止的任务优先；进入提醒区间的任务会标红并显示倒计时。
- **任务库完整留档**：「未结束」包含进行中和等待下一次触发的任务；「已结束」保留已完成与已过期任务，可复用或永久删除。
- **灵活的多次触发规则**：每天可在时间轴设置多个检查点；每周 / 每月可指定执行日，并只保留一个检查点。单次任务支持按日期或按时长设置截止时间。
- **本地提醒**：任务剩余时间低于阈值时发送系统通知，同一任务在同一触发区间内持续处于提醒区间时不会重复刷屏。
- **可定制外观**：支持 RGB 数值和系统取色器调整强调色，应用到按钮、导航选中状态等界面元素。
- **紧凑侧栏**：侧栏可收起为仅显示图标，把更多空间留给任务列表。
- **托盘与单实例**：关闭窗口可选择退出或隐藏到托盘；同一时间只允许运行一个实例。
- **便携数据**：数据库、设置和错误日志都位于程序旁的 `data` 目录，备份或迁移时直接复制整个目录即可。

## 快速开始

1. 将 `TaskList.exe` 放到一个当前用户有写权限的目录。
2. 双击运行程序。
3. 点击主页右上角的「+ 新建任务」。
4. 填写任务内容，按需设置重要等级、开始时间、截止时间和多次触发规则。
5. 点击「保存任务」。

首次启动会在程序所在目录自动创建：

```text
data/
├── tasks.db
├── settings.json
└── error.log
```

> 不建议把程序放在 `Program Files` 等默认只读目录中，否则可能无法创建或写入数据。

## 使用说明

### 新建与编辑任务

任务编辑窗口包含以下内容：

- **任务内容**：必填，最多 500 个字符。
- **重要等级**：0–10，数字越小越优先。
  - `0` 紧急
  - `1–3` 重要
  - `4–6` 次要
  - `7–9` 普通
  - `10` 不重要
- **任务类型**：
  - **单次**：完成后直接归档。
  - **多次**：可选择「每天…」「每周…」「每月…」，具体规则在下方时间轴与执行日中选择。
- **触发时间轴**：点击时间轴添加检查点，拖动检查点调整时间；选中后可用时间框精确到秒。
  - **每天**：可添加多个检查点，相邻检查点之间构成一个任务区间。
  - **每周 / 每月**：只保留一个检查点，并分别通过星期按钮或日期格子选择执行日。
  - 每月 1–28 日始终可用；29–31 日单独分组，只有存在该日期的月份才会触发。
- **开始时间**：可选；未指定时按任务创建时间开始。
- **截止时间**：
  - 多次任务可设置整体截止时间；不设置时触发会一直持续。
  - 单次任务可在「选择日期」和「选择时长」之间切换；时长支持天、时、分、秒，保存时换算为具体截止时间。
  - 不指定截止时间表示永久有效。
- **预览区**：保存前显示触发规则、当前区间、整体截止时间和单次任务的时间范围。

截止时间必须晚于开始时间，且不能早于当前时间。修改触发类型、检查点、执行日或开始时间后，该任务的完成进度会重置。

### 主页

主页按「重要等级 + 剩余时间」综合排序，展示任务 ID、标题、重要等级、当前触发区间和完成按钮。

- 点击任务卡片右侧的「✓ 完成」标记完成。
- 双击任务卡片可修改任务。
- 右键任务卡片可修改、标记完成或删除。
- 临近截止的任务会标红，并显示剩余时间倒计时。

单次任务完成后进入任务库的「已结束」；多次任务完成当前区间后从主页隐藏，到达下一次触发时间后自动重新出现。

### 任务库

任务库顶部有两个标签，并显示对应数量：

- **未结束**：所有尚未归档的任务，包括正在进行和等待下一次触发的任务。
- **已结束**：已完成或已过期的任务。

在任务库中：

- 未结束标签中的多次任务可能显示「本次已完成」，表示等待下一次触发；「未开始」表示尚未到达开始时间。
- 双击任务可打开编辑窗口；已结束任务会进入复用流程，保存后创建新任务。
- 右键未结束任务可修改或删除。
- 右键已结束任务可「复用并修改（创建副本）」或永久删除。
- 复用已结束任务会创建一条新任务，原归档记录仍保留。

### 多次触发规则

多次任务按本地日历计算触发检查点，再转换为 UTC 参与比较。相邻两个检查点构成一个任务区间；完成当前区间后，任务会隐藏到下一次触发。

- **每天**：在选定的多个检查点触发。例如 09:00、13:00、18:00 会把一天分成三个区间。
- **每周**：选择一个检查点，并勾选周一到周日中的执行日；未勾选的日期不触发。
- **每月**：选择一个检查点，并勾选每月 1–31 日中的执行日。29–31 日只在存在该日期的月份触发。
- 任务开始时间晚于当前时间时，不会提前显示。
- 完成当前区间后，任务会从主页移除，直到下一次触发时间。
- 设置了整体截止时间的多次任务，到达截止时间后会自动归档，不再产生新触发。

### 提醒与通知

在设置中可以调整「重要提醒阈值」，默认是任务总时长的 5%，可设置范围为 0.5%–50%。

当任务剩余时间低于该比例时：

- 主页和任务库中的任务标题会标红。
- 主页卡片会显示剩余时间倒计时。
- 如果开启了系统通知，会通过托盘气泡发送提醒。

同一任务在同一触发区间内持续处于提醒区间时只提醒一次；启动时已经处于提醒区间的任务不会立即补发通知。关闭通知后不会产生新的系统提醒。

### 设置

设置页包含：

- **重要提醒阈值**：控制任务何时进入紧急状态。
- **默认首个触发时间**：新建多次任务时时间轴上的第一个检查点，可在单个任务中修改。
- **系统通知**：开启或关闭任务提醒。
- **强调色 RGB**：手动输入 RGB 数值，或使用「选择颜色」打开系统取色器。
- **关闭主窗口时**：选择「直接退出」或「最小化到托盘」。
- **数据目录**：点击路径可直接打开数据文件夹。

修改后需要点击「保存设置」才会生效。

### 托盘与单实例

- 托盘图标双击可重新打开主窗口。
- 托盘右键菜单支持「打开任务清单」「新建任务」「退出」。
- 如果设置了关闭到托盘，关闭主窗口时程序会隐藏到通知区域。
- 重复启动程序时，会提示任务清单已经在运行，请从托盘打开。

## 时间与数据

### 时间规则

- 所有时间在内部和数据库中统一保存为 **UTC ISO-8601**，例如 `2026-11-05T12:48:10.000Z`。
- 界面始终按系统当前时区显示本地时间。
- 切换系统时区不会改变任务的实际时刻。
- 每天 / 每周 / 每月的触发检查点按本地日历和本地时间计算。

### 数据文件

数据目录位于 `TaskList.exe` 同级的 `data` 文件夹：

| 文件 | 用途 |
| --- | --- |
| `data/tasks.db` | SQLite 任务数据库（WAL 模式） |
| `data/settings.json` | 提醒阈值、默认首个触发时间、通知、关闭行为、强调色等设置 |
| `data/error.log` | 未处理异常日志 |

- 首次运行会自动创建数据库和默认设置。
- 数据库使用 WAL 模式，正常退出时会执行检查点并合并 WAL 文件。
- 设置文件损坏时会尝试备份为 `.bad-时间戳` 文件，并使用默认设置启动。
- 需要清空数据时，先退出程序，再删除整个 `data` 目录。
- 备份或迁移时，退出程序后复制 `data` 目录即可。

## 构建

### 环境要求

- Windows 10 / 11 x64
- .NET 8 SDK
- 目标机器需要 .NET 8 Desktop Runtime（使用框架依赖构建或发布时）

### Debug / Release 构建

在仓库根目录执行普通 Debug 构建：

```powershell
dotnet build TaskList/TaskList.csproj
```

输出位置：

```text
TaskList/bin/Debug/net8.0-windows/TaskList.exe
```

Release 构建：

```powershell
dotnet build TaskList/TaskList.csproj -c Release
```

输出位置：

```text
TaskList/bin/Release/net8.0-windows/TaskList.exe
```

普通构建会保留 Windows x64 所需的 SQLite 原生库，并清理其他平台的运行时文件。

直接运行源码：

```powershell
dotnet run --project TaskList/TaskList.csproj
```

### 单文件发布

项目内置 `win-x64` 发布配置，生成框架依赖的 Windows x64 单文件：

```powershell
dotnet publish TaskList/TaskList.csproj -p:PublishProfile=win-x64
```

输出位置：

```text
TaskList/bin/publish/win-x64/TaskList.exe
```

该版本为单文件，目标机器仍需安装 **.NET 8 Desktop Runtime**。

如需完全自包含、无需预装 .NET 运行时的版本：

```powershell
dotnet publish TaskList/TaskList.csproj -p:PublishProfile=win-x64 `
  -p:SelfContained=true `
  -p:PublishDir=bin\publish\win-x64-self-contained\
```

自包含版本体积会明显增大，但可以直接复制到未安装 .NET 的 Windows x64 机器运行。

## 项目结构

```text
TaskList/
├── Program.cs                  # 入口、单实例、全局异常处理
├── Data/                       # 路径、设置、SQLite、UTC 时间工具
├── Models/                     # 任务模型与触发类型
├── Services/                   # 触发计算、排序、完成、归档等核心规则
├── UI/                         # 主窗口、主页、任务库、设置和任务编辑
└── Properties/PublishProfiles/ # 单文件发布配置
```

## 设计边界

- 仅支持 Windows x64。
- 数据完全保存在本地，不提供云同步或多设备同步。
- 单用户、单实例运行，不包含账号和权限系统。
- 程序依赖可写的数据目录；请避免放在受保护的系统目录中运行。
